# Інструкції для Claude

- Кожна сторінка — окремий самодостатній HTML-файл у корені репозиторію (наприклад `money.html`).
- **GitHub Pages вимкнено** на прохання користувача: сторінки більше не публікуються на `rokushnir.github.io`. Репозиторій лише зберігає вихідні файли. Сторінки для людей живуть на `study.spe.org.ua` (UA-хостинг) — їх завантажують через адмінку (див. останній пункт). Не вмикати Pages і не повертати `CNAME`.
- Інтерактивні робочі зошити Bubbles лежать у папці `bubbles/` (`bubbles/<назва>.html`); додавай кожен новий зошит карткою на `bubbles/index.html`.
- Після створення сторінки додай її в таблицю в `README.md`.
- Не комітити службові файли (скриншоти перевірок тощо).
- Друк / PDF (для всіх сторінок): верстка для друку має бути щільною — мінімум сторінок A4, без великих порожнин. Якщо на сторінці лишається понад 1/5 вільного місця, щось не так: розтягни графіки чи блоки, щоб заповнити місце, або стисни їх, щоб уміститись. Ховай у друці кнопки, навігацію і поля вводу (показуй значення текстом), зменшуй шрифти й відступи, не лишай заголовок самотнім унизу сторінки. Приклад реалізації з автопідбором висоти графіків — `finshliakh.html` (`fitPrint`).
- **Публікація на study.spe.org.ua — автоматична.** Після кожного push у `main` GitHub Actions (`.github/workflows/study-sync.yml` → `tools/study-sync.mjs`) надсилає змінені сторінки на сайт (правила — `study-sync.json`; секрет `STUDY_SYNC_TOKEN` з адмінки сайту). Тому **після кожної правки, яку просить користувач, одразу зливай її в `main`** (PR і merge) — користувач цього хоче завжди, окремо не питай. Змінена сторінка оновлюється на сайті з тим самим розділом і кодом; нова з'являється в адмінці в «Нерозподілених» — скажи користувачу перетягнути її в розділ (`/bi/`, `/biznes/`, `/pidlitki/`, `/taim-menedzhment/`…). Посилання: `https://study.spe.org.ua/<розділ>/<назва-файлу-без-.html>/`.
- SPE_sheets — **єдине джерело** цих сторінок (копії в `bubbles/_src/spe` — лише знімок для архіву, там не правити). Репозиторій має бути приватним.
- **Браузер і сторонні сервіси (UA-хостинг, панелі, налаштування GitHub тощо):** якщо немає швидшого способу без участі користувача, відкривай вкладку в його Chrome (Claude in Chrome) і працюй там через застосунок — користувач сам дасть доступ. Не відсилай його робити це вручну, поки такий спосіб доступний. Якщо сесія хмарна і Chrome недоступний — одним рядком попроси відкрити сесію в застосунку Claude на комп'ютері з розширенням Claude in Chrome.
